# 已知问题与适用边界

适用于当前源码基线 **0.14.7 build47**。以下问题没有因为发布到 GitHub 而自动修复；仓库说明不代表对所有系统、素材或达芬奇版本的兼容保证。

## 已确认需要改进的问题

| 问题 | 当前影响 | 后续方向 |
| --- | --- | --- |
| 历史合板失败可能被复用 | 素材及同步设置未变化时，重新点击合板可能跳过重新计算，继续保留失败／无声结果。相关失败签名未包含算法版本。 | 增加明确的失败重试及所选片段重新分析入口，区分成功缓存与失败记录。 |
| 合板报告未总是保留具体失败原因 | 输出可能只有“原始 WAV 匹配失败”，无法从导出包区分相似度不足、多点核查失败等。 | 保留每条候选和最终拒绝原因，支持追踪原始失败记录。 |
| 部分界面仍有旧原声回退提示 | 个别提示仍写沿用 PGM 原声，但当前导出只使用已匹配主 WAV，其余留空。 | 统一界面、处理状态和实际导出策略。 |
| 波形同步仅支持固定偏移 | 长条录音存在漂移，或参考声与主声音差异大时，可能整体拒绝匹配。 | 分段一致性诊断及明确的漂移处理方案，避免未经核实就改动源声音。 |

不要把“再次点击”“任务结束”或“可以导出”当作合板已成功。当前应检查每条 PGM 是否有有效 WAV 关联及实际覆盖区间。没有真实媒体时，单凭失败报告不能认定现场未录声音。

## 三种结果需要分别判断

1. **合板是否成功**：PGM 是否找到了原始 WAV，并建立了可靠源位置关系。
2. **导出是否完整**：期望的基准和备选是否已摆放，代理及声音覆盖是否符合预期。
3. **达芬奇导入是否通过**：已输出的片段是否按计划进入对应轨道，来源、位置及链接是否匹配。

`.resolve-report.json` 的成功结果主要对应第 3 项。第 1 项失败而允许静音导出时，第 3 项仍可能成功。它不表示所有 PGM 都有声音。

## 按当前规则保持无声的区间

- 未找到匹配主 WAV，或主 WAV 没有覆盖的部分。
- 所有摄影机代理无覆盖而使用 `PGM_REF` 的画面区间。

不自动用 PGM／代理内嵌原声补这些位置，也不把相邻录音拉长到未录制区域。声音轨被禁用则是另一种情况：片段仍在轨道上，只是没有播放。

## 剪辑与交换边界

- 工作流以硬切为基础，叠化、变速、复杂嵌套或重组后的往返需另行测试。
- 多机位资源中的某个角度可以局部缺录；有角度名称不代表它全程都有画面。
- PGM 参考画面不会自动恢复为原始摄影机画质。
- 台词匹配是初排工具。重复台词、改词、跳句、即兴表演及无台词素材仍需要人工判断。
- 备选移动改变剪辑位置，不会对不同表演自动变速以完全贴合基准。
- 达芬奇原生 XML 往返可能量化声音源入点。声音 AAF 应从原粗剪时间线交付，不以视频回套后的 XML 时间线替代。
- BWF／iXML 自定义字段不保证都传递到最终 AAF；左右合并的新 WAV 使用新身份，原身份由对应表记录。
- 导入失败可能撤回本次时间线但保留部分媒体池条目；媒体池有素材不等于新时间线已成功建立。

## 安装与运行范围

OCR 使用 macOS Vision。当前源码面向 macOS / Python 3.12，Windows 和 Linux 未受支持。Intel 与 Apple Silicon 的依赖不能直接混用；Intel 语音依赖应使用仓库约束文件，详见[安装与运行](installation.md)。

完整离线安装需要事先准备依赖、模型和运行环境；下载源码 ZIP 不等于已具备离线环境。模型、CPU、时长、编解码格式及存储读速都会影响处理耗时，本仓库不承诺统一识别速度。

## 提交可复现问题

建议先用可公开或自行生成的短样复现，提供：

- 代码版本、macOS、CPU 架构与达芬奇版本。
- 帧率、素材数量、是否含停机、左右分文件或长条录音。
- 具体操作、预期结果、实际结果。
- 脱敏的导出／导入报告，涉及的轨号与记录时间位置。

工程文件、报告和路径可能包含真实作品、人员、文件名或存储信息，提交前请检查内容。不要直接公开真实演出素材、完整台本、原始录音或未脱敏工程。
