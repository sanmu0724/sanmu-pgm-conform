# 操作流程

适用流程：现场 PGM 硬切参考 → daily 代理多机位 → 达芬奇粗剪 → 声音交付与视频原片回套。

## 1. 准备素材

每场拍摄登记在独立场次中，准备：

- 对 PGM 完成硬切分割后，从达芬奇导出的 Final Cut Pro 7 XML。
- XML 引用的完整 PGM 文件，可有多条。
- 各机位对应的 daily 代理；保留原始帧率、首帧时码和完整长度。
- 该场主 WAV，或一组组配对的左／右单声道 WAV。
- 需要整理跨场备选时，准备台本。没有台本也可人工摆放。

切点 XML 保持原 PGM 顺序和完整范围，不删片、不变速；不同 XML 不要重复登记同一 PGM。摄影机停机、换卡产生多条代理可同时导入，不要求每条 PGM 都有全部机位全程覆盖。

## 2. 项目、场次与机位

新建或打开 `.pgmproj`，选择保存位置。填写自定义拍摄日期和类型，设置机位数量，再登记该场文件。

项目保存的是引用和处理结果，不包含媒体。外接盘或 NEXIS 的工作区需先挂载；换电脑后要保证引用路径可访问。先保留稳定的目录与文件名，再开展剪辑。

在“机位与同步”选择机位样例，框选标号区域并配置稳定前缀，例如：

| 画面标号示例 | 匹配内容 | 机位 |
| --- | --- | --- |
| `B0001`、`B0002` | `B` | B |
| `440_0001`、`440_0002` | `440` | C |
| `D003C001`、`D004C002` | `D` | D |

旧素材可以配置无标号机位，其他样式按场次单独设置。测试 ROI 后进行批量识别，核对未知、冲突及切点附近的结果。标号变化或 ROI 调整后，重新识别并保存。

“同步已核对”是人工检查记录，不会自动纠正错误时码。用实际画面对照 PGM 与代理，确认视频同步；声音合板不能替代这一检查。

## 3. 原始 WAV 合板

在“声音合板”选择模式：

| 模式 | 使用条件 |
| --- | --- |
| 波形 | PGM 有可用参考声；用波形建立原始主 WAV 与 PGM 的关系。 |
| 仅时码 | PGM 与原始 WAV 的真实时码已经可靠同步。 |

单个 mono 或 stereo WAV 直接作为主声音。左右分文件时同时添加，可自动识别常见命名；自动配对不明确时指定左右。采样率、长度、时码及共同字段冲突时应先核对文件身份，不要把不同录次强配成左右声道。

检查每条 PGM 的声音覆盖，而不只看整体任务是否结束：

- 成功：有效区间引用主 WAV。
- 部分覆盖：仅覆盖区间有声音，其余留空。
- 整条失败：该 PGM 无 WAV 音频输出。
- `PGM_REF`：即使原始 WAV 覆盖，该画面回退段也不附声音。

**当前版本有失败缓存复用问题。** 在输入和设置未变化时，重复点击合板可能仍沿用旧失败，不能把它视为重试成功。遇到这种情况先保存项目和诊断信息，见[已知问题](known-issues.md)；不要通过修改源时码或随意降低判断标准掩盖失败。

## 4. 整理与摆放备选

基准和备选可以任意顺序登记。在“PGM 手动编排”的“素材整理”页，以台本编号组织完整 PGM；可编辑覆盖范围、调整轨道和人工核实。短条、无台词条可以手工关联到一行或一段台本。

选定一场通条作为基准后，进入“基准时间线对齐”：

1. 基准按 PGM 顺序组成 V1，横轴改为实际时间。
2. 可通过“建立映射并自动对齐”将已整理的备选粗排到对应剧情附近，或直接人工摆放。
3. 左窗查看基准，右窗查看备选。选中哪一类片段，播放／暂停控制对应窗口，另一窗暂停。
4. 拖动、输入位置或调整轨道后，检查最终位置，再点击已有的“确认所选对齐”。
5. 保存编排，再保存项目。

整理页的台本核实与对齐页的最终位置确认是两种状态。对齐页蓝色表示尚未确认，绿色表示已确认；修改位置后需再次确认。当前导出可包含已摆放的蓝条，正式交剪前应核查。未摆放的素材不参与备选导出。

备选保留完整 PGM 和原速。不同表演的时长不必一致，位置以剧情、台词和人工判断确定；不改写摄影机源时码来强求跨场同步。

## 5. 导出多机位 XML

三种输出都需要确定基准坐标：

| 模式 | 内容 |
| --- | --- |
| 仅基准 | 基准场次完整多机位时间线。 |
| 仅备选 | 已摆放的备选，保留相对于基准的位置。 |
| 基准＋备选 | 基准 V1 与上方分轨备选一次导出。 |

导出保留硬切，必要时在代理覆盖变化处分段。同一条 PGM 在媒体池中是多机位源，在剪辑轨道上可能对应很多切开的片段。

保留 `.fcpxml`、同名 `.resolve.lua`、有声音时的 `.resolve-audio.aaf`、对应表及报告。左右 WAV 合并生成的“配对立体声 WAV”媒体目录也必须一并交接，不能只复制 XML。

## 6. 导入达芬奇

1. 创建与素材帧率一致的项目；已有验证流程使用 25fps。
2. 挂载所有媒体目录。
3. 通过“工作区 → 脚本 → 三木_导入多机位XML”选择新的 `.fcpxml`；菜单由桌面安装器安装，见[安装说明](installation.md)。
4. 等待导入及校验完成，确认新时间线存在，并检查同名 `.resolve-report.json`。
5. 核查 Vn/An 对应、机位切换、声画链接以及若干开头、中间和结尾的实际同步。

助手自动读取内部音频 AAF，不需手动再导入。新导入创建新时间线，不会自动更新旧的粗剪时间线。

默认仅启用主轨画面和声音，备选轨禁用。需要观看备选时启用其视频及对应声音，避免同时播放不同表演的音轨。选择“链接所选”，确认有 WAV 覆盖的片段能与对应视频一起移动或修剪。

如果只进媒体池、没有新时间线，先检查报告是否失败并撤回了新时间线。如果某条视频没有声音，先查看导出前的合板记录；成功导入报告不会补出未匹配的录音。

## 7. 声音交付与原片回套

声音部门的粗剪 AAF 应从达芬奇原粗剪时间线输出，按双方约定交付参考视频和媒体。软件包内的 `.resolve-audio.aaf` 只负责导入适配，不能代替剪辑后的交付。

视频回套时：

1. 登记完整、正确的代理与原片配对。
2. 从达芬奇导出粗剪后的剪辑 XML。
3. 在软件“原片回套”先选剪辑 XML，再选对应的 `proxy_original_map.json`。
4. 生成原片 XML 并在达芬奇核对，之后再进行调色和最终制作。

跨场同名文件不应仅凭名称猜配。组合导出的对应表包含相关场次身份；明确的 `PGM_REF` 仍保留 PGM 画面，不自动变成摄影机原片。

视频 XML 往返可能丢失声音亚帧信息，因此先从原粗剪工程完成声音交付，再做视频原片回套。录音元数据能否支持最终多轨回套，应与声音部门用短样核验。
